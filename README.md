# LiveSubtitleTranslator

A native macOS menu-bar app that listens to your Mac's system audio, transcribes
the speech on-device, translates it to Chinese, and shows the result as a
floating subtitle overlay — in near real time.

It is designed for personal accessibility and comprehension: watching a talk,
following a meeting, or understanding a video in another language. Everything
runs locally. No audio or transcripts are sent to a cloud service.

```
System audio  →  transcribe (English)  →  translate (→ Chinese)  →  on-screen subtitles
```

- **Capture:** Core Audio process taps (no microphone, no screen recording).
- **Transcription (ASR):** Parakeet (default) or WhisperKit, on the Apple Neural Engine.
- **Translation:** Apple Translation (default), NLLB, or Hunyuan-MT, all on-device.
- **Display:** a draggable, lockable AppKit overlay panel that floats above other windows.

> **Privacy:** Inference is 100% local. Model *weights* are downloaded once from
> Apple / Hugging Face and cached; speech audio and transcripts never leave your Mac.

## Requirements

| Requirement | Detail |
|---|---|
| **macOS** | 26.5 or later (uses Core Audio process taps + Apple Translation) |
| **Mac** | Apple Silicon strongly recommended (ASR/translation run on the ANE/GPU) |
| **Xcode** | A version whose SDK targets macOS 26.5 |
| **Disk** | Up to several GB for cached on-device models (see [Models](#on-device-models)); model weights are not included in this repo |
| **Network** | Needed to download the selected models/assets from the Settings page before first real use; offline afterward |

This is a **menu-bar agent** (`LSUIElement`): it has no Dock icon and no main
window. After launch, look for its icon in the menu bar.

## Importing the project into Xcode

The repo uses a standard `.xcodeproj` with Swift Package Manager dependencies
resolved automatically by Xcode — there is no `Podfile` or workspace to set up.

1. **Clone the repo:**
   ```bash
   git clone https://github.com/M-Chimiste/livetranslation
   cd livetranslation
   ```

2. **Open the project:**
   ```bash
   open LiveSubtitleTranslator.xcodeproj
   ```
   (or `File ▸ Open…` in Xcode and pick `LiveSubtitleTranslator.xcodeproj`).

3. **Let Swift Package Manager resolve dependencies.** On first open, Xcode
   fetches and resolves the package graph (this can take a few minutes):
   - [`FluidAudio`](https://github.com/FluidInference/FluidAudio) — Parakeet ASR
   - [`argmax-oss-swift`](https://github.com/argmaxinc/argmax-oss-swift) / WhisperKit — WhisperKit ASR
   - [`swift-transformers`](https://github.com/huggingface/swift-transformers) — tokenizers + Hugging Face Hub model downloads
   - [`mlx-swift`](https://github.com/ml-explore/mlx-swift) — Hunyuan-MT inference

   If resolution stalls, use `File ▸ Packages ▸ Reset Package Caches`, then
   `Resolve Package Versions`.

4. **Select the scheme and destination:** scheme `LiveSubtitleTranslator`,
   destination **My Mac**.

5. **Signing:** the project ships with development team `4H8Z97B24M`. To build on
   your own machine, open the target's *Signing & Capabilities* tab and set your
   own team. The app uses the **App Sandbox + hardened runtime**; the included
   [`LiveSubtitleTranslator.entitlements`](LiveSubtitleTranslator/LiveSubtitleTranslator.entitlements)
   grant audio-input and network-client access plus a few specific exceptions —
   leave them as-is unless you know you need to change them.

> `Info.plist` is generated by Xcode (`GENERATE_INFOPLIST_FILE = YES`). Add new
> Info.plist keys through `INFOPLIST_KEY_*` build settings, not by committing a
> plist file.

## Building & running

### From Xcode (recommended for day-to-day work)

- **Build:** `Cmd-B`
- **Run:** `Cmd-R` — the app launches as a menu-bar item.
- **Test:** `Cmd-U`

### From the command line

```bash
# Build (Debug)
xcodebuild -project LiveSubtitleTranslator.xcodeproj \
  -scheme LiveSubtitleTranslator -configuration Debug build

# Build (Release)
xcodebuild -project LiveSubtitleTranslator.xcodeproj \
  -scheme LiveSubtitleTranslator -configuration Release build
```

### Running tests

```bash
# All unit + UI tests
xcodebuild -project LiveSubtitleTranslator.xcodeproj \
  -scheme LiveSubtitleTranslator -destination 'platform=macOS' test

# A single unit test (Swift Testing — replace the trailing function name)
xcodebuild -project LiveSubtitleTranslator.xcodeproj \
  -scheme LiveSubtitleTranslator -destination 'platform=macOS' test \
  -only-testing:LiveSubtitleTranslatorTests/LiveSubtitleTranslatorTests/appSettingsDefaultsAreDeterministic
```

Unit tests use **Swift Testing** (`import Testing`, `@Test`, `#expect`) and live
in a single struct `LiveSubtitleTranslatorTests`, so `-only-testing` paths take
the form `LiveSubtitleTranslatorTests/LiveSubtitleTranslatorTests/<funcName>`.
UI tests use XCTest in `LiveSubtitleTranslatorUITests`.

## Usage

### First launch

1. Run the app. Its icon appears in the **menu bar** (no Dock icon, no window).
2. Open **Settings… ▸ Backends** and select/download the ASR and translation
   models you want to use. Model weights are **not included** in the app or repo.
   Local NLLB and Hunyuan-MT expose warm-up buttons in Settings; ASR and Apple
   Translation assets download/prepare when the selected live path first starts.
3. The **first time** you start live subtitles with a real backend, macOS prompts
   for **system audio recording** permission. Subsequent launches are offline and
   faster once models/assets are cached.

### Menu-bar controls

Click the menu-bar icon to open the menu:

| Item | What it does |
|---|---|
| **Pipeline / Live / Overlay** (status lines) | Show current pipeline state, live-session state, and overlay visibility |
| **Start Live Subtitles** | Begin capturing audio and producing subtitles |
| **Stop Live Subtitles** | Stop the live pipeline |
| **Show / Hide Overlay** | Toggle the subtitle panel's visibility |
| **Lock / Unlock Overlay** | Locked = click-through and fixed in place; unlocked = draggable/resizable |
| **Reset Overlay Position** | Move the overlay back to its default location and size |
| **Open Settings…** | Open the Settings window |
| **Quit** | Exit the app |

### Typical flow

1. Start playing the audio/video you want subtitles for.
2. Menu bar ▸ **Start Live Subtitles**.
3. Subtitles appear in the floating overlay. **Unlock Overlay** to drag/resize it
   where you want, then **Lock Overlay** so it stays put and clicks pass through
   to whatever is behind it.
4. Menu bar ▸ **Stop Live Subtitles** when done.

### Settings

Open via **Open Settings…**. Notable options:

- **Audio source** — System Output or a Selected App.
- **ASR backend** — Local Parakeet (default), Local WhisperKit, or Remote LAN.
  Parakeet offers v3 (multilingual) and v2 (English-only); WhisperKit offers
  tiny / large-v3 / large-v3 turbo.
- **Translation backend** — Apple Translation (default), Local NLLB, Local
  Hunyuan-MT, or Remote LAN.
- **Source / target language** — defaults to English → Simplified Chinese
  (Traditional Chinese also available).
- **Latency profile** — Fast, Balanced (default), or More Accurate.
- **Overlay** — background opacity, lock state, frame.
- **Diagnostics** — when enabled, records per-stage latency metrics (capture →
  ASR → translation → render).

Switching backends takes effect at runtime — no restart required.

## On-device models

Model weights are **not bundled** with this repository or the app target. Before
first real use, open **Settings… ▸ Backends** to choose the ASR and translation
backends and download/warm up the required models. These are **local-inference**
models — only the weights/assets are fetched and cached on your Mac.

| Backend | Model | Source |
|---|---|---|
| Parakeet (default ASR) | `parakeet-tdt-0.6b-v3` (multilingual) / `-v2` (English) | FluidAudio |
| WhisperKit | `tiny` / `large-v3` / `large-v3 turbo` | argmax / WhisperKit |
| NLLB | NLLB-200 distilled, CoreML conversion | [`cstr/nllb-200-coreml-128`](https://huggingface.co/cstr/nllb-200-coreml-128) (HF) |
| Hunyuan-MT | Hy-MT2-1.8B (8-bit) | `mlx-community/Hy-MT2-1.8B-8bit` (HF) |
| Apple Translation (default) | System translation assets | Apple |

If a download or model load fails, the overlay shows a short status string and
Settings keeps the detailed error.

> **License notice:** The Meta/Facebook NLLB model family is published under a
> Creative Commons Attribution-NonCommercial license (CC BY-NC 4.0), including
> the upstream `facebook/nllb-200-*` models on Hugging Face. Treat the Local NLLB
> backend as personal/non-commercial unless you have confirmed separate rights.
> Always check the upstream model card/license for every model you download.

## Troubleshooting

- **No subtitles after Start** — confirm macOS granted audio-recording permission
  (System Settings ▸ Privacy & Security), and that audio is actually playing.
- **First run is slow / appears to hang** — it's downloading a model. Watch the
  overlay status line; let it finish, then it's cached.
- **Overlay won't move** — it's locked. Menu bar ▸ **Unlock Overlay**.
- **Package resolution errors in Xcode** — `File ▸ Packages ▸ Reset Package
  Caches`, then `Resolve Package Versions`.
- **Want a permission-free dry run** — use the Mock ASR / Mock translation
  backends, which produce sample subtitles without audio access or downloads.
